# Tube5 workflow

## Verification scope

The owner requires short development iterations and verification focused on the
current investigation. Select meaningful checks for the changed code; do not run
the full host media suite for every diagnostic build.

- For hardware decoding investigations, check decoder lifecycle, buffer ownership,
  timestamps, picture integrity, and the native build as relevant to the change.
- Do not rerun bridge, PC catalog/search, or unrelated playback/UI tests when
  those paths are not being changed. Legacy PC workflows are not the product goal.
- Do not repeat a passed check without a new change, failure, or concrete concern
  affecting its coverage. After a local correction, rerun the affected checks.
- Run broad suites only when explicitly requested or when a concrete regression
  requires that scope. Explain any expansion briefly.
- Once focused checks and the native build pass, proceed to the authorized console
  transfer. Avoid adding research or extra features before handing off that build.

## Console iteration

Keep the user's app-open/app-closed status across turns. A confirmed close remains
valid until the user says they have reopened the app; do not ask for confirmation
again during that interval. Preserve the preceding build on activation and transfer
only changed artifacts. Never replace the executable while the app is open.

Keep console tokens, private logs, photos, and packaged artifacts containing tokens
out of Git. Public synthetic fixtures generated by this project may be committed.
